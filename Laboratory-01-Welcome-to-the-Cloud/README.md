# Laboratory Activity 1 – Welcome to the Cloud

## Mission Overview
This was my onboarding mission as a newly-hired Junior Cloud Infrastructure Engineer Trainee at CloudNova Technologies. Before touching any real cloud infrastructure, I had to prove I could work inside a Linux environment, document my work properly, and set up a version-controlled portfolio on GitHub. Basically, cloud engineering 101.

## Objectives
- Access and use a cloud-based Linux environment via KillerCoda
- Navigate around the Linux OS like I actually know what I'm doing
- Pull basic system information (distro, kernel, CPU, memory, disk)
- Organize files and directories properly
- Set up and maintain a professional GitHub repository
- Document everything using Markdown

## Activities Performed
1. Created a new user (`clomboy`) with Bash, a home directory, and sudo access
2. Logged in as the new user and checked username, working directory, and hostname
3. Investigated the environment — Linux distro, kernel version, CPU specs, memory, and disk space
4. Built out the folder structure for the portfolio
5. Wrote an `about-me.md` with some personal info and a bit of personality
6. Created the GitHub repo `CCM101-clomboy` and organized everything inside
7. Committed and pushed everything to GitHub

## Linux Commands Used
- `adduser`, `usermod` — creating the user and giving sudo access
- `su` — switching to the new user
- `cat /etc/os-release`, `uname -r`, `lscpu`, `free -h`, `df -h` — gathering system info
- `mkdir`, `cd`, `mv`, `ls` — navigating and organizing files/folders
- `nano` — writing and editing markdown files
- `git init`, `git add`, `git commit`, `git push` — version control and pushing to GitHub

## Skills Learned
This activity was a good refresher (and for some parts, a first-time learning experience) on navigating a Linux terminal, creating user accounts with proper permissions, and pulling system info using different commands. I also got more comfortable organizing files and folders in a clean, logical way, and writing documentation in Markdown instead of just plain text. Most importantly, I got hands-on practice with basic Git commands — init, add, commit, push — which honestly felt like leveling up from just knowing the theory to actually using version control for something real.
